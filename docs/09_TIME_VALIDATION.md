# 時間帯の過去資料照合

2026-10-29の追加依頼に対応し、既存の時間帯計算を過去の一次資料と比較した。アプリの「検証・参照リンク」ページは`#/sources`で開く。検索条件を保持し、時間帯の説明、使い方、ヘッダー、フッターから移動できる。

## 判定

初回の照合では、旧ルール`reference-unvalidated-v1`の帰宅帯に早期退場が含まれないことを確認した。その後の「検証結果を元に時間帯の計算を見直して、早期退場も考慮する」という追加依頼により、J1の帰宅の始点を開始110分後＋徒歩時間から60分後＋徒歩時間へ変更した。新ルールは`reference-early-departure-v2`とする。

60分は国立競技場の1試合のゲート観測を参考にした共通の仮定であり、全国の駅の混雑開始を実測した値ではない。試合終了見込み110〜130分、来場帯、帰宅の終端は維持する。従来表示していた区間を残したまま、帰宅帯を50分広げた。`validatedForRealUse: false`を維持し、より早い退場、ゲート・駅での待機、全国への再現性は未検証と明記する。

開始時刻をK、公式徒歩分数をWとすると、J1の来場は`[K−150分, K−15分)`、帰宅は`[K＋60分＋W, K＋130分＋W＋90分)`。15時開始の飛田給駅W=5分では、帰宅が16:55〜18:45から16:05〜18:45になる。19時開始では20:55〜22:45から20:05〜22:45になる。デモの計算は変更しない。

|検証対象|比較方法と結果|判定できないこと|
|---|---|---|

|飛田給駅の昼・夜の運行案内|2025-05-25と2025-06-14の2試合。来場27本・帰宅22本の公表時刻がすべて現行区間内|実際の運行・乗客数・混雑の的中率。2試合とも同じ会場・駅|

列車は上下線を分けて数える。同じ時刻の別列車を重複として削除しない。試合前は飛田給駅の到着、試合後は同駅の出発を使用し、新宿駅の時刻と混同しない。通常列車は収録対象に含まれない。計算区間は始点を含み終端を含まない。

ハーフタイムの加算は、公式集計の試合時間を経過時間の目安に換算する仮定である。ボールが動いている時間を示すAPTとは区別する。年平均5点を5試合の標本や、個別試合の信頼区間として扱わない。

## 保存と再現

出典URL、発行者、対象期間、掲載箇所、採用した事実、用途、限界、年別秒数、列車の全時刻を`data/time-evidence.json`に保存した。型は`contracts/time-evidence.ts`、入力検証は`app/src/data/validateTimeEvidence.ts`、比較計算は`app/src/domain/timeValidation.ts`にある。記事本文や図版はアプリへ転載しない。

比較計算は本体の`calculateWindows`を呼ばずに実装し、テストで結果を相互照合する。照合時のルール番号と6係数、見直し前のルールを`baselineReview`に保存し、想定外の変更時は画面で再確認が必要と表示する。徒歩分数は現在の公式アクセス値を使う。日付が異なる過去の徒歩実測としては扱わない。安全なHTTPS出典、参照ID、実在日付、数値、時刻、同一方向の列車重複を検証し、不正な資料はエラー表示にする。日をまたぐ列車はこの資料形式では扱わず、曖昧に同日として取り込まない。

J1のrulesに任意項目`earlyDepartureAfterMinutes`を追加し、60を設定する。未指定の旧データでは従来の`matchEndEarliestAfterMinutes`を使う。指定値は0以上かつ終了見込みの下限以下の整数に限り、null、文字列、非有限値、小数を拒否する。デモはこの追加項目を使わない。日程更新処理も新ルールを出力するため、更新後に110分へ戻らない。元の5係数・JSONキー・日程・履歴・アクセスデータ・保存形式を維持する。

```sh
cd app
npm run verify:time
```

このコマンドは保存済み資料と現在の係数・徒歩分数から比較結果のJSONを出力する。外部取得、係数変更、日程やお気に入りの書き換えは行わない。`predictionAccuracy`はnullである。資料の最新確認と集計結果の再計算を区別し、資料確認日は自動更新しない。

## ページと確認項目

ページには検証結果、年平均の比較、観測事例、運行案内の比較、全時刻を開く欄、8資料の参照URLを掲載する。各資料に対象期間・発行者・用途・限界を付ける。既存の22会場の公式アクセスと380試合の出典も、折りたたみ欄から参照できる。スマートフォンでは比較表を項目別の縦表示にする。

デモモードでは、この検証がJ1実データの参考計算を対象にすることを説明し、J1の検証ページへのリンクを出す。架空の日程や分数を実測で検証したかのように表示しない。データ入力エラー、リンク、検索条件の維持、保存・再読み込み、既存機能の回帰、画面幅、キーボード、拡大表示、本番ビルドを確認する。
