# J1実データの追加仕様

2026年10月29日の追加依頼「実際に使えるようにデータを取り込む。とりあえずJ1の試合とそのホームゲームが行われる最寄り駅が対象」に対応した仕様です。元の資料のデモ限定・外部取得なし・初期日固定はデモモードに適用します。J1モードでは以下の仕様を適用します。元のデモデータと機能は維持します。

## 対象と出典

2026/27明治安田J1リーグの20クラブ・全380試合を対象にします。収録期間は2026-08-01〜2027-06-30です。2026-10-29の確認時点で22会場と39駅、41組の会場・駅の対応を収録しています。ホームクラブの本拠地から会場を推測せず、各試合の公式日程に掲載された会場を使います。国立競技場での開催、水戸の水戸信用金庫スタジアムでの開催、長居の2会場を区別します。

Jリーグ公式の検索結果と未終了試合の詳細ページから、対戦・日付・時刻・会場・節・状態・日程注記を取得します。取得した事実と出典URL、確認時刻は`data/sources/j1-2026-27.json`に保存します。試合ごとの出典と確認時刻は画面にも表示します。記事本文、写真、ロゴはアプリに取り込みません。

アクセス駅は会場・クラブ・鉄道会社の公式案内から確認した駅です。直線距離が最短の1駅に限定せず、複数の公式アクセス駅を収録します。鶴川・清水はバス利用を明記します。駅から会場までの徒歩分数が確認できない場合はnullとし、経路案内だけを表示します。公園入口までの時間やバス乗車時間を、スタジアムまでの徒歩時間として使いません。

## 日程の状態

|状態|扱い|
|---|---|
|scheduled|開催日・時刻・会場が確定した予定|
|completed|終了済み。開催日の件数には含め、時間帯は計算しない|
|date_tbd|公式注記に複数の候補日がある。候補日の各日に別枠で表示し、開催件数には含めない|
|time_tbd|日付と会場は確定、開始時刻は未定。開催件数に含め、時間帯は計算しない|
|venue_tbd|会場が未定。全地域の検索で別枠表示し、駅へ結び付けない|
|postponed / cancelled|延期・中止。変更案内を表示し、開催件数や時間帯には含めない|

公式の一覧に日付が付いていても、詳細注記に「or」と複数日があれば確定日とは扱いません。条件付きで変更される「可能性」の日付はconditionalDatesに保存し、現在の予定と分けて表示します。開催候補日・条件付き候補日は検索、カレンダー、駅詳細、お気に入りで確認できます。未定を確定に置き換えたり、ホームクラブから未定会場を補ったりしません。

試合IDはシーズン・ホーム・アウェイの組み合わせで固定します。公式URLや日付が変わっても同じ試合として扱い、再取得時に日付・時刻・会場の変更を履歴へ追加します。初回取得以前の変更履歴は収録していません。

## 更新と失敗時の扱い

`app/update-j1.cmd`または`npm run data:update`で手動更新します。公式検索の250件上限による取りこぼしを防ぐため、対象期間を3分割します。未終了試合の詳細は順番に取得します。外部通信はHTTPSのwww.jleague.jpだけに限定し、リダイレクトや不明なデータ形式はエラーとして扱います。アクセス案内は別途人が確認して`data/j1-access.json`を更新します。

380試合、クラブごとのホーム19試合、38節それぞれ10試合、重複、会場対応、出典URL、日付と参照関係を検証します。候補を一時ファイルへ保存して再検証した後、既存データを`data/j1.previous.json`へ退避し、`data/j1.json`を置き換えます。取得・検証が失敗した場合は現在の表示用データを保持してエラーを表示します。既存データ自体が読めない場合も、勝手に初期化しません。

`npm run data:build`は保存済みの取得事実から再構築するコマンドです。通信や最新情報の確認は行いません。開発中は更新後にブラウザーを再読み込みし、本番ビルドでは再ビルドして反映します。同日の追加依頼による公開・定期取得・履歴保存は[実験公開と日次更新](10_PUBLIC_RELEASE.md)を参照してください。公式ページの構造変更、未知の会場、シーズン変更は取得処理と対応表の確認が必要です。

画面上部に最終確認日を表示し、確認から7日以上経つと更新確認の案内を表示します。古い情報の空結果は「試合がない」と断定せず、更新確認が必要と表示します。閲覧時の自動取得は行いません。

## 時間帯と保存

既存の時間帯計算は、J1では「参考計算・予測精度は未検証」と明記します。実測・混雑予測・公式推奨ではありません。公式案内に徒歩分数がある駅と確定した試合だけで計算し、バス利用・徒歩分数未収録・未定・終了済みでは計算しません。デモの計算は維持します。

2026-10-29の早期退場への対応依頼により、J1の帰宅の始点を開始110分後＋徒歩時間から60分後＋徒歩時間へ変更します。終了見込み110〜130分、来場帯、帰宅の終端は維持します。任意の係数`earlyDepartureAfterMinutes`を追加し、旧データで未指定なら従来の始点を使います。根拠・見直し前後の比較・限界は[時間帯の過去資料照合](09_TIME_VALIDATION.md)と、アプリの検証・参照リンクページに記載します。全国共通の予測精度を検証できたという意味ではありません。

J1を既定で開き、初期日は日本時間の今日にします。`?data=demo`で旧デモを開けます。J1のお気に入りは専用キーへ保存し、初回だけ対応するデモの駅を引き継ぎます。J1の変更・全解除でデモの保存値を消しません。ファイルのImport／Exportやサーバー保存は追加しません。

## 確認項目

全件数と参照関係、国立開催、水戸の開催会場、未定の候補日、条件付き候補日、バス利用、終了分、更新が古い場合、収録範囲外、更新失敗時の保持を確認します。旧デモの検索・変更案内・計算・保存・共有・操作を回帰テストします。画面は360・390・768・1440pxと200%拡大で確認し、型検査・単体テスト・ブラウザーテスト・本番ビルドを実行します。結果は`app/VERIFICATION.md`に記録します。
