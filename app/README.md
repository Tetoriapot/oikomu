# オイコム

[公開版を開く](https://tetoriapot.github.io/oikomu/) · デモ版・実験公開中。公開版は日本時間の毎日0:00に日程更新を開始し、最終成功日時と取得履歴を右上の「更新情報」で確認できます。

日付と駅・地域・スタジアムから、J1の試合と開催会場のアクセス駅を確認するWebアプリです。2026年10月29日に公式日程を確認し、2026/27シーズンの20クラブ・380試合・22会場・39駅を収録しています。初期日は日本時間の今日です。未定の日程・会場は未定のまま表示します。

以前のデモは`http://127.0.0.1:5187/?data=demo`で利用できます。関東5会場・7駅・架空8チーム・24試合、2026年11〜12月、初期日2026年11月7日というデモの条件は維持しています。「使い方」からも両モードを切り替えられます。

## このPCで起動する

依存ライブラリは導入済みです。`app/start-demo.cmd`をダブルクリックするか、PowerShellで次を実行してください。

```powershell
cd C:\Projects\OIKOMU_Codex_Demo_Spec_v1\app
.\start-demo.cmd
```

ターミナルに表示されたLocal URLをブラウザーで開いてください。通常は`http://127.0.0.1:5187/`です。使用中ならViteが別のポートを選びます。終了は起動したターミナルでCtrl+Cを押してください。

ランチャーは通常のNode.jsを使い、見つからない場合はこのPCのCodex同梱Node.jsを使います。個人のブラウザープロファイルや設定は変更しません。

## 操作

右上の「更新情報」から最終成功日時・取得履歴・変更履歴を確認できます。「ライト」「ダーク」で表示を切り替え、「Help」から操作方法と参考時間帯の説明を開けます。全画面に「デモ版・実験公開中」を表示します。

日付と場所を入力し、場所は表示された候補から選んで「検索する」を押します。場所を空欄にすると全地域になります。入力中の条件は検索を実行するまで結果に反映されません。候補は矢印・Enterで選択でき、Escapeで閉じられます。

「一覧」「月間」で表示を切り替えます。カレンダーは月曜始まりの42日表示です。月を移動すると、その月の1日を選択します。駅の詳細では当日の予定、次の5件、関連会場と別のアクセス駅を確認できます。試合の詳細には現在の会場、注意時間帯、変更履歴、計算の説明があります。

星ボタンで駅を登録・解除します。お気に入り画面では登録順に当日の予定と次の1件を表示します。「URLをコピー」で日付・場所・表示形式を共有できます。コピーに失敗した場合は選択できるURL欄を開きます。ローカルURLは他の端末からは開けません。

「使い方」の「今日へ戻る」は日付だけを初期化します。デモでは「デモ基準日へ戻る」です。「お気に入りをすべて解除」は確認後に現在のモードの登録だけを削除します。

「検証・参照リンク」では、過去の試合時間・人流・列車の運行案内と、現在の参考時間帯を比較できます。時間帯の説明からも開けます。参照URL一覧には8資料の対象期間・発行者・用途・限界を掲載しています。「参照URL一覧へ」で一覧に移動し、会場アクセスと各試合の日程出典は折りたたみ欄から開けます。

## J1の日程を更新する

このPCでは`app/update-j1.cmd`をダブルクリックしてください。公式サイトから全380試合と未終了試合の注記を取得するため、数分かかります。コマンドでの更新は次のとおりです。

```sh
cd app
npm run data:collect
```

成功後はブラウザーを再読み込みしてください。本番ビルドを表示している場合は`npm run build`を再実行します。公開版はGitHub Actionsで日本時間の毎日0:00に更新を開始します。実行待ちと処理時間により反映が遅れる場合があります。ローカル版は手動更新です。最終確認から7日以上経つと画面上部に更新確認の案内を表示します。

取得失敗、未知の会場、件数不足、不正データでは処理を中止し、現在の`data/j1.json`を保持します。エラーの内容を確認し、通信エラーなら時間を置いて再実行してください。公式ページの形式や会場が変わった場合は、取得処理や`data/j1-access.json`の対応を確認します。更新は同時に複数起動しないでください。

駅・経路・徒歩分数は公式アクセス案内を確認して登録したもので、日程更新コマンドでは更新しません。各会場の公式リンクから最新案内を確認できます。取得手順とデータ項目は[実データ仕様](../docs/08_REAL_DATA.md)、出典は[出典一覧](../SOURCES.md)を参照してください。

更新の仕組みと手動公開の操作は[実験公開と日次更新](../docs/10_PUBLIC_RELEASE.md)を参照してください。取得記録は`data/history/`、索引は`data/collection.json`へ保存します。従来の`data:update`は履歴を追加しない互換コマンドとして残しています。

## データと保存

`../data/j1.json`と`../data/demo.json`をビルド時に同梱します。型は`../contracts/types.ts`を参照し、重複したコピーを作りません。実行時に型・参照・状態・日付・時刻・履歴・収録範囲・外部URLを検証します。致命的な不整合は読み込みエラーとして表示します。

お気に入りとライト／ダークの選択をlocalStorageに保存します。表示モードのキーは`oikomu:theme:v1`です。J1は`oikomu:j1:v1:favorites`、デモは従来の`oikomu:demo:v1:favorites`です。J1の保存値がまだない場合は、デモから対応する駅を引き継ぎます。J1で編集・全解除してもデモの保存値は変更しません。

```json
{"schemaVersion":1,"stationIds":["st-tobitakyu"]}
```

未知IDと重複IDを除き、破損した保存値では空の状態で開始します。保存できない環境では案内を表示し、開いている間だけ保持します。保存失敗時の変更や解除は、次回起動時には残らない場合があります。J1の全解除は空の登録を保存して、再起動時にデモの登録を引き継ぎ直さないようにします。デモの全解除は従来どおりデモのキーだけを削除します。

確定した検索条件はハッシュURLに保存します。許可するパラメーターはdate・month・view・placeです。ハッシュより前の`?data=demo`でデモを選択し、それ以外はJ1を表示します。戻る・進む・直接アクセス・再読み込みに対応し、不正な日付はJ1では今日、デモでは基準日に戻します。検索履歴をlocalStorageには保存しません。ファイルのImport／Export機能はありません。

```sh

```

ブラウザーテストはローカルでMicrosoft Edge、GitHub ActionsではChromiumを使います。独立したテスト用プロファイルを作り、ユーザーの保存情報は使いません。`playwright.config.ts`が127.0.0.1:5187で開発サーバーを起動します。既に同じデモが起動している場合は再利用します。

ビルド結果は`dist/`です。`npm run preview`でビルド結果を確認できます。検証結果と受け入れ条件の対応は[VERIFICATION.md](VERIFICATION.md)を参照してください。

## 制約

J1の日程は確認時点の公式情報です。対象は2026/27 J1リーグで、J2・J3・カップ戦・他のイベント・鉄道運行情報は含みません。開催候補日や条件付きの変更候補は開催件数に含めず、別に表示します。試合会場は現在のstadiumIdから判定し、ホームチームの本拠地から推測しません。終了・延期・中止・未定では時間帯を計算せず、旧会場や旧日程には変更案内を表示します。変更履歴は初回取り込み後に検出した変更だけです。

時間帯は既存の仮定に基づく参考計算で、混雑の実測・予測ではありません。J1では公式案内で確認できた徒歩分数だけを使い、徒歩分数が未収録の駅やバス利用の駅では計算しません。デモでは元のサンプル分数を使います。対象試合がなくても、駅が空いていることを意味しません。

過去5シーズンの年平均試合時間は終了見込みと整合しましたが、旧計算には早期退場が含まれない事例も確認しました。追加依頼により、J1の帰宅の始点を開始60分後＋公式徒歩時間へ見直しています。15時開始・徒歩5分なら、帰宅は16:55〜18:45から16:05〜18:45になります。試合終了の見込み110〜130分、来場帯、帰宅の終端、デモの計算は維持します。

60分は国立競技場の1試合のゲート観測を参考にした共通の仮定です。より早い退場や駅の混雑開始を保証せず、表示外にも移動があります。数値比較は`npm run verify:time`で再現でき、資料と判定方法は[時間帯の過去資料照合](../docs/09_TIME_VALIDATION.md)に記録しています。参照ページで見直し前後を比較でき、日程を更新しても新しい計算を維持します。列車の公表時刻の包含を混雑予測の的中率として扱いません。

日程の手動更新時だけ公式サイトへアクセスします。通常のアプリ操作では外部データを取得せず、端末の保存情報も送信しません。出典リンクはクリック時に開きます。ログイン、サーバー側保存、課金、AI、利用分析、外部フォントはありません。公開運営や定期取得の利用条件の確認、駅ごとの混雑予測精度の評価は別の作業です。元の検討事項は`../docs/06_REAL_DATA_ROADMAP.md`に保持しています。
